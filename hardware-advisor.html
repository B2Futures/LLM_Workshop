How this works

What this tool does

This tool works backwards from what you want to run. Instead of starting with hardware and asking what fits, you start with your goal — a specific model, a use case, or a GPU tier — and it tells you what to buy. Recommendations come in three tiers: Minimum (it runs, barely), Recommended (good experience), and Ideal (best possible). For servers, multi-GPU configurations are shown alongside single-GPU options.

The three paths

Run a specific model
You already know which model you want — Llama 3.3 70B, Gemma 4 12B, etc. The tool calculates minimum VRAM for each quantization level and recommends hardware that gives you a good experience at that model size.
Best model for a use case
You know what you want to do — coding assistant, document analysis, creative writing — but not which model. The tool recommends the best current model for that use case and tells you what hardware runs it well.
GPU tier explorer
You want to understand the landscape — what entry-level GPUs can run vs high-end vs datacenter. Each tier shows which GPU families it covers and what models become available.

Hardware tiers explained

Minimum
The model loads and runs. Generation will be slow and context will be limited. Acceptable for occasional use or testing, not for daily productivity.
Recommended
Comfortable generation speed (10+ tok/s), reasonable context length, stable operation. This is the sweet spot for most users.
Ideal
Fast generation, long context, headroom to run higher quantizations. Best experience available for this model size.

Key terms

VRAM
Memory on the graphics card. The model weights must fit here. A 12B Q4_K_M model needs ~7.5 GB just for weights — everything else (context, KV cache) comes from the remaining headroom.
Quantization (Q4, Q6, Q8)
Compression applied to model weights. Q4 = smallest and fastest, Q8 = largest and highest quality. Q4_K_M is the most common sweet spot — roughly half the VRAM of full precision with minimal quality loss.
tok/s (tokens per second)
Generation speed. Under 3 tok/s feels slow. 10–20 tok/s is comfortable. 30+ tok/s feels fast. Speed depends on model size, GPU, and how many layers fit in VRAM.
KV cache
Memory used to store conversation context. Grows as conversations get longer. Longer context = more VRAM consumed beyond the model weights.
Tensor parallelism
A multi-GPU technique that splits model layers across cards. Lets you run models that don't fit on a single GPU. NVLink between cards gives better bandwidth than PCIe.
NVLink
NVIDIA's high-speed interconnect between GPUs. Much faster than PCIe for multi-GPU inference. Available on datacenter cards (A100, H100) and some consumer cards (RTX 3090, 4090 with NVLink bridge).
Unified memory (Apple Silicon)
On Apple Silicon, CPU and GPU share the same memory pool. A 64 GB M4 Max effectively has 64 GB of "VRAM". Bandwidth is lower than discrete GPUs but the large pool enables very large models on consumer hardware.

About the data

Recommendations are based on built-in data covering current GPU specifications, model VRAM requirements, and measured performance estimates. When connected to an LM Preview backend with a web-capable model, the tool will fetch current model releases and benchmark data to supplement the built-in information. Built-in data is updated periodically — check the source badge at the top of the page.
